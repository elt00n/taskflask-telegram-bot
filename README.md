# Telegram Task Bot

Менеджер задач для личных и групповых чатов Telegram, написанный на Go.

Проект находится на начальном этапе разработки. Согласованная архитектура,
пользовательские сценарии и план реализации описаны в
[docs/architecture.md](docs/architecture.md).

## Основные возможности

- быстрое создание задач из сообщения;
- общие задачи и разграничение прав редактирования;
- списки, сортировка и фильтры;
- персональные и повторяющиеся напоминания;
- экспорт и последующая синхронизация с календарями.

## Текущее состояние

Создан фундамент Go-приложения и первые доменные модели: задача, пользователь, чат,
участник чата и назначенный участник задачи. Модель задачи поддерживает проверку
обязательных полей, значения по умолчанию, задачи без срока и события с временем
начала и окончания.

Правила доступа закреплены отдельным сервисом и автоматическими тестами: все
активные участники чата могут видеть его задачи, редактировать могут создатель и
назначенные участники, а удалять — только создатель.

PostgreSQL подключён через пул `pgx`. Версионируемые SQL-миграции автоматически
применяются при старте, а задачи, назначения, профили пользователей, чаты и членство
сохраняются после перезапуска. In-memory реализации репозиториев оставлены для
быстрых unit-тестов бизнес-логики.

Создатель и назначенные участники могут менять название, описание, важность,
расписание и дедлайн, а также завершать задачу. Удаление доступно только создателю и
является мягким: задача скрывается из обычных списков, но сохраняется для истории и
будущего восстановления.

Парсер быстрых команд поддерживает обычные задачи, время `сегодня` и `завтра`, дни
недели, календарные дедлайны, важность и usernames участников. Точный синтаксис и
ограничения описаны в [docs/commands.md](docs/commands.md).

Telegram transport подключён через long polling. Работают команды `/start`,
`/help`, `/task`, `/tasks` и `/tasks @username`. Бот постоянно хранит usernames
известных участников и обновляет профиль при каждом сообщении. Пользователь должен
хотя бы один раз обратиться к боту в конкретном чате, прежде чем его можно будет
назначить там по username.

## Локальный запуск

Для локального запуска нужен Docker Desktop. Запустить PostgreSQL:

```bash
docker compose up -d postgres
```

Создать локальный файл настроек и вставить в него токен от BotFather:

```bash
cp .env.example .env
```

```env
TELEGRAM_BOT_TOKEN=ваш_токен
```

Локальный `DATABASE_URL` уже совпадает с параметрами `compose.yaml`. Файл `.env`
загружается автоматически и исключён из Git. Запустить бота:

```bash
go run ./cmd/bot
```

Остановить бота можно сочетанием `Ctrl+C`. Остановить локальную базу:

```bash
docker compose stop postgres
```

Данные PostgreSQL находятся в именованном Docker volume и сохраняются после
остановки контейнера. Команда `docker compose down -v` удаляет этот volume вместе с
данными, поэтому её следует использовать только для осознанного полного сброса.

Задачи, пользователи, чаты, членство и сопоставление `@username` с Telegram ID
хранятся в PostgreSQL и не очищаются при перезапуске бота.

Запустить все тесты:

```bash
go test ./...
```

Запустить тесты с детектором конкурентных ошибок:

```bash
go test -race ./...
```

Проверить код статическим анализатором Go:

```bash
go vet ./...
```

Все доступные настройки перечислены в [`.env.example`](.env.example). Настоящие
токены и пароли не должны попадать в Git или выводиться в логи.
